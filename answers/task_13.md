# Завдання 13. Чому вебсервіс не бачить базу (середнє)

**Умова.** У проєкті Compose сервіс `web` при старті пише у журнал `connection refused` під час підключення до бази:

```yaml
services:
  web:
    image: shop-web:1
    environment:
      DB_HOST: localhost
      DB_PORT: "8001"
    ports:
      - "8080:8000"
  db:
    image: postgres:16
    ports:
      - "8001:5432"
```

Колега пропонує додати до `db` ключ `expose: ["5432"]` і прописати в `DB_HOST` IP-адресу контейнера бази, яку показала команда `docker inspect`. Знайдіть помилки в налаштуванні, поясніть, чому пропозиція колеги ненадійна, і запропонуйте виправлення. Відповідь має містити й висновок, чи потрібен у сервісу `db` запис `ports`.

Напишіть відповідь своїми словами під рядком нижче (8–12 речень).

Відповідь:

У наведеному конфігурації Docker Compose є дві ключові помилки. По-перше, сервіс `web` використовує `DB_HOST: localhost`, але в мережі Docker кожен контейнер має власний ізольований локальний хост; для зв'язку між сервісами слід використовувати ім'я сервісу бази даних (`db`). По-друге, порт бази `8001:5432` опубліковано на хості, проте вебсервіс має звертатися до контейнера бази всередині внутрішньої мережі Compose на стандартний порт `5432`, а не на хостинговий порт `8001`. Пропозиція колеги додати `expose: ["5432"]` та використовувати IP-адресу через `docker inspect` є вкрай ненадійною, оскільки IP-адреси контейнерів динамічні та змінюються при кожному перезапуску стека. Правильним виправленням є встановлення `DB_HOST: db` та `DB_PORT: "5432"` у змінних середовища сервісу `web`. Запис `ports` для сервісу `db` потрібен лише в тому разі, якщо до бази даних необхідно підключатися із зовнішніх відносно Docker хоста інструментів (наприклад, локальних GUI-клієнтів девелопера), і не є обов'язковим для зв'язку з `web`.

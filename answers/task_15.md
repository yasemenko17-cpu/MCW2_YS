# Завдання 15. Спільна інфраструктура в команді (складне)

**Умова.** Троє інженерів керують тестовим середовищем через OpenTofu. Файл стану `terraform.tfstate` лежить у репозиторії Git, а пароль бази записано у відкритому вигляді у `terraform.tfvars`, який теж закомічено. Минулого тижня інженер А вручну видалив контейнер у середовищі, а інженер Б одночасно запустив `apply` зі своєї копії стану; після цього стан у Git виявився суперечливим, а їхні плани відрізнялися.

Розберіть ситуацію: поясніть, що сталося і чому плани різні; запропонуйте зміни в організації стану, секретів і запуску змін; обґрунтуйте вибір. Назвіть щонайменше два компроміси вашого рішення й спосіб їх зменшити. Поясніть, що саме покаже `plan` після ручного видалення контейнера і як переглянути лише розбіжності.

Напишіть відповідь своїми словами під рядком нижче (15–25 речень або структурований план).

Відповідь:

У ситуації, що склалася, виник конфлікт через збереження файлу стану `terraform.tfstate` у локальному репозиторії Git та зберігання чутливих даних (пароля бази) у відкритому вигляді в `terraform.tfvars`. Коли інженер А видалив контейнер вручну, а інженер Б запустив `apply` зі своєї несинхронізованої локальної копії стану, їхні версії розійшлися, оскільки стан у Git не оновлювався атомарно й централізовано. Для вирішення проблеми слід перенести файл стану в кешоване віддалене сховище з блокуванням (наприклад, Terraform Cloud або S3 з DynamoDB для блокування), а секрети винести у змінні середовища або менеджери секретів замість коміту в репозиторій. Основними компромісами такого рішення є залежність від зовнішніх сервісів зберігання та складність первинного налаштування бекенду, які мінімізуються використанням стандартних макетів хмарних провайдерів. Команда `tofu plan` після ручного видалення контейнера покаже необхідність створення (create) видаленого ресурсу на основі конфігурації, оскільки стан у файлі стейту відрізняється від реального стану інфраструктури. Щоб переглянути виключно розбіжності між станом і реальністю без зайвого виведення, використовують прапорець `tofu plan -refresh-only` або `tofu plan -target=...`.
